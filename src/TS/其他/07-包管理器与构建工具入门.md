# 包管理器与构建工具入门

> **面向读者**：有 Go 后端经验的开发者。Go 的依赖管理（`go.mod`/`go.sum`）和构建（`go build`）是官方统一的标准。前端生态则是**多工具并存**——npm/yarn/pnpm 负责依赖管理，Vite/webpack 负责构建打包。理解它们的分工和演进，能帮你快速定位到"该用哪个工具"。

---

## 一、包管理器：npm / yarn / pnpm 对比

前端包管理器相当于 Go 的 `go mod`，但选择和版本更多：

| 特性                | npm                    | yarn                 | pnpm                   |
| ------------------- | ---------------------- | -------------------- | ---------------------- |
| 出现时间            | 2010（最早）           | 2016                 | 2017                   |
| 锁定文件            | `package-lock.json`    | `yarn.lock`          | `pnpm-lock.yaml`       |
| 安装策略            | 扁平 node_modules      | 扁平 node_modules    | **硬链接 + 隔离**       |
| 磁盘空间            | 重复占用                | 重复占用              | 全局 store + 硬链接     |
| 安装速度            | 慢                     | 中                   | **快**                 |
| monorepo 支持       | 原生 workspaces        | yarn workspaces      | **pnpm workspace**     |
| 严格性              | 宽松（Ghost 依赖）      | 一般                  | **严格（禁止 Ghost 依赖）** |

::: tip 为什么 Go 开发者应该关注 pnpm？

Go module 的设计理念：**每个模块独立存储，全局共享缓存，依赖解析确定**。pnpm 的实现最接近这一理念：

```
Go module cache:
  $GOPATH/pkg/mod/
    github.com/gin-gonic/
      gin@v1.9.0/
      gin@v1.10.0/

pnpm store:
  ~/.pnpm-store/
    vue@3.4.0/
    react@18.0.0/

pnpm node_modules（硬链接）:
  my-app/node_modules/vue → ~/.pnpm-store/vue@3.4.0
```

:::

### 1.1 安装对比

```bash
# Go
go get github.com/gin-gonic/gin@v1.9.0

# npm
npm install vue@3.4.0

# yarn
yarn add vue@3.4.0

# pnpm（推荐）
pnpm add vue@3.4.0
```

### 1.2 常用命令对比

| 操作             | Go             | npm              | pnpm                |
| ---------------- | -------------- | ---------------- | ------------------- |
| 初始化           | `go mod init`  | `npm init`       | `pnpm init`         |
| 安装依赖         | `go mod tidy`  | `npm install`    | `pnpm install`      |
| 添加依赖         | `go get pkg`   | `npm install pkg` | `pnpm add pkg`      |
| 移除依赖         | 手动编辑       | `npm uninstall`  | `pnpm remove`       |
| 更新依赖         | `go get -u`    | `npm update`     | `pnpm update`       |
| 运行脚本         | `go run`       | `npm run dev`    | `pnpm dev`          |
| 查看过时依赖     | `go list -u -m` | `npm outdated`  | `pnpm outdated`     |

## 二、package.json vs go.mod

```json
// package.json
{
  "name": "my-app",
  "version": "1.0.0",
  "private": true,
  "type": "module",

  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview",
    "lint": "eslint src --ext .ts,.tsx"
  },

  "dependencies": {
    "vue": "^3.4.0",
    "pinia": "^2.1.0"
  },

  "devDependencies": {
    "typescript": "^5.3.0",
    "vite": "^5.0.0",
    "@types/node": "^20.0.0",
    "eslint": "^8.50.0"
  }
}
```

```go
// go.mod
module github.com/myapp

go 1.22

require (
    github.com/gin-gonic/gin v1.9.0
    // 无 devDependencies 概念——所有依赖在编译时平等
)
```

| 概念                  | `package.json`                 | `go.mod`                    |
| --------------------- | ------------------------------ | --------------------------- |
| 项目名称              | `name`                         | `module`                    |
| 版本                  | `version`                      | 无（由 git tag 决定）        |
| 运行时依赖            | `dependencies`                 | `require`                   |
| 开发时依赖            | `devDependencies`              | **无此概念**                 |
| 脚本                  | `scripts`（`dev`/`build` 等）  | 无（通过 Makefile 或 task）  |
| 版本范围              | `^3.4.0`（semver 语义化版本）   | `v1.9.0`（精确版本）         |
| 依赖锁定              | `package-lock.json`            | `go.sum`                    |
| 本地包替换            | workspace / `"file:"`          | `replace`                   |

::: info semver 语义化版本

```
^3.4.0  → 兼容 3.x.x（>=3.4.0 <4.0.0）
~3.4.0  → 兼容 3.4.x（>=3.4.0 <3.5.0）
3.4.0   → 精确版本
*       → 任意版本（不推荐）
```

类比 Go 中 `go get pkg@v1.9.0` 总是精确版本，前端 semver 更灵活但也更容易引入意料之外的更新。

:::

## 三、node_modules 的结构

这是前端开发者最常遇到的"槽点"之一：

```bash
# Go 的 module cache（干净，按版本隔离）
$GOPATH/pkg/mod/
  github.com/
    gin-gonic/gin@v1.9.0/    ← 一个版本一份
    gin-gonic/gin@v1.8.0/    ← 另一个版本一份

# npm 的扁平 node_modules（可能产生 Ghost 依赖）
my-app/
  node_modules/
    vue/                     ← 直接依赖
    react/                   ← 直接依赖
    @vue/                    ← 直接依赖
    scheduler/               ← ?? 谁引入的？(Ghost 依赖)
    # 所有依赖平铺到一层，可能引用到"未在 package.json 中声明"的包

# pnpm 的隔离 node_modules（最接近 Go 的设计）
my-app/
  node_modules/
    .pnpm/                   ← 硬链接存储区
    vue@3.4.0/               ← 硬链接
    react@18.0.0/            ← 硬链接
    # 只能引用 package.json 中显式声明的依赖
```

::: caution 不要提交 node_modules

```bash
# .gitignore —— 必须包含
node_modules/
dist/
```

类比 Go 中 `vendor/` 目录通常也不提交到仓库（除非特殊需要）。`node_modules` 动辄数百 MB，提交它会严重影响 Git 仓库性能。

:::

## 四、Vite：新一代构建工具

Vite 是目前最主流的前端构建工具，类比 Go 的 `go build` + `go run` 的结合体：

```ts
// vite.config.ts
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';      // Vue 项目
// import react from '@vitejs/plugin-react'; // React 项目
import { resolve } from 'path';

export default defineConfig({
  plugins: [vue()],

  // 开发服务器
  server: {
    port: 3000,
    proxy: {
      '/api': {
        target: 'http://localhost:8080',    // 代理到 Go 后端
        changeOrigin: true,
      },
    },
  },

  // 构建配置
  build: {
    outDir: 'dist',
    sourcemap: true,
    rollupOptions: {
      output: {
        manualChunks: {
          vendor: ['vue', 'pinia'],          // 第三方库单独打包
        },
      },
    },
  },

  // 路径别名
  resolve: {
    alias: {
      '@': resolve(__dirname, 'src'),
    },
  },
});
```

### 4.1 Vite 的核心特性

| 特性                  | Vite 实现               | 类比 Go                     |
| --------------------- | ----------------------- | --------------------------- |
| 开发服务器            | 按需编译 HMR           | `go run` + `air` 热重载     |
| 生产构建              | Rollup 打包             | `go build` 输出二进制        |
| HMR（热更新）         | 修改代码 → 秒级更新页面 | `air` 自动重启              |
| TypeScript            | 原生支持（esbuild 转译）| 编译器原生支持               |
| 静态资源处理          | 自动引入 hash           | `//go:embed`                |

### 4.2 HMR（Hot Module Replacement）

```
Go 开发循环：
  修改代码 → go build（秒级） → 重启进程 → 重新请求

Vite HMR 开发循环：
  修改代码 → esbuild 转译（毫秒级） → 仅替换修改的模块 → 页面即时更新
  保持应用状态不变（Vue/React 组件状态不丢失）
```

### 4.3 生产构建与 go build 对比

```bash
# Go：输出单二进制
go build -o server ./cmd/server
# 输出：server（一个文件，包含所有依赖）

# Vite：输出静态资源包
vite build
# 输出：dist/
#   ├── index.html
#   ├── assets/
#   │   ├── index-abc123.js    # JS 打包
#   │   ├── vendor-xyz789.js   # 第三方库
#   │   └── style-456def.css   # CSS 打包
#   └── favicon.ico
```

| 构建输出         | Go                    | Vite                        |
| ---------------- | --------------------- | --------------------------- |
| 产物形式         | 单二进制文件          | 多个静态文件（HTML + JS + CSS）|
| 部署方式         | 直接运行二进制        | 部署到 Nginx/CDN            |
| 依赖打包         | 静态链接到二进制中    | 打包到 JS bundle 中          |
| 环境要求         | 无（自包含）          | 需要 Web 服务器              |

## 五、Webpack 概念（了解即可）

Vite 是当前主流，但 Webpack 仍有许多存量项目：

```js
// webpack.config.js（历史对比用）
module.exports = {
  entry: './src/main.ts',
  output: {
    filename: 'bundle.js',
    path: path.resolve(__dirname, 'dist'),
  },
  module: {
    rules: [
      {
        test: /\.ts$/,
        use: 'ts-loader',      // Loader：处理非 JS 文件
        exclude: /node_modules/,
      },
    ],
  },
  plugins: [
    new HtmlWebpackPlugin({    // Plugin：扩展功能
      template: './index.html',
    }),
  ],
};
```

| 概念      | Webpack             | 类比 Go                     |
| --------- | ------------------- | --------------------------- |
| Loader    | 处理非 JS 文件      | 类似 build tag + `//go:embed` |
| Plugin    | 扩展 Webpack 功能   | 类似 Go generate 注解        |
| Code Splitting | 代码分割      | 类似包级别的条件编译          |
| Tree Shaking   | 摇树优化      | 未使用的导出不会包含          |

::: tip

作为新手，你大概率会用 **Vite** 而非 Webpack。了解 Webpack 的目的是：
- 能看懂存量项目的配置
- 理解 Loader/Plugin 的抽象概念（类似 Go 的 `//go:generate`）

:::

## 六、模块联邦（Module Federation）——微前端概念

Webpack 5 引入的模块联邦允许**不同独立部署的应用之间共享代码**，类似于 Go 中多个微服务共享一个公共库：

```js
// 宿主应用（Host）
new ModuleFederationPlugin({
  name: 'host',
  remotes: {
    // 加载远程微应用
    app1: 'app1@http://localhost:3001/remoteEntry.js',
    app2: 'app2@http://localhost:3002/remoteEntry.js',
  },
  shared: {
    // 共享公共依赖，避免重复加载
    vue: { singleton: true },
    pinia: { singleton: true },
  },
});
```

```
微前端架构            微服务架构
┌──────────┐        ┌──────────┐
│ Header App│        │  Auth    │
│ (React)   │        │ Service  │
├──────────┤        ├──────────┤
│ Main App │        │  Order   │
│ (Vue)    │        │ Service  │
├──────────┤        ├──────────┤
│ Footer   │        │  Payment │
│ (Angular)│        │ Service  │
└──────────┘        └──────────┘
  共享 Vue/React 库    共享 Proto/API
```

## 七、Bad vs Best

### Bad：提交 node_modules

```diff
# .gitignore ❌ 没有忽略 node_modules
+ node_modules/
+ dist/
+ .env
```

```bash
# 结果：每次 clone 要下载数百 MB，diff 彻底失效
```

### Best：首选 pnpm + Vite

```bash
# 新项目初始化推荐
pnpm create vite my-app --template vue-ts
# 或
pnpm create vite my-app --template react-ts

cd my-app
pnpm install
pnpm dev                  # 启动开发服务器
```

```json
// 严格管理依赖版本
{
  "dependencies": {
    "vue": "3.4.0",       // 精确版本，不使用 ^ 或 ~
    // 或
    "vue": "^3.4.0"       // 接受 patch 更新
  },
  "pnpm": {
    "overrides": {         // 强制覆盖版本（类似 Go replace）
      "vue": "3.4.0"
    }
  }
}
```

::: warning 依赖版本管理原则

```bash
# Go 的做法（推荐前端也采用）
go get vue@v3.4.0         # 精确版本
# go.mod 中显示：require github.com/... vue v3.4.0

# 前端常见问题
"vue": "^3.4.0"            # ^ 允许 minor 更新
# 今天：3.4.0
# 明天 CI：3.5.0（破坏性变更！）

# 最佳实践：
# 1. 使用锁文件（pnpm-lock.yaml）锁定所有传递依赖
# 2. 使用 CI 检查：pnpm install --frozen-lockfile
# 3. 使用 Renovate/Dependabot 自动管理依赖更新
```

:::

## 总结

| 概念             | 前端推荐选择      | Go 类比                    |
| ---------------- | ----------------- | -------------------------- |
| 包管理器         | **pnpm**          | `go mod`                   |
| 依赖描述文件     | `package.json`    | `go.mod`                   |
| 锁文件           | `pnpm-lock.yaml`  | `go.sum`                   |
| 依赖存储         | `.pnpm-store`     | `$GOPATH/pkg/mod`          |
| 开发构建         | `vite dev` (HMR)  | `air` (热重载)             |
| 生产构建         | `vite build`      | `go build`                 |
| 代码分割         | dynamic import    | 包级分离（不同 binary）     |
| 微前端           | Module Federation | 微服务架构                 |
| 依赖版本管理     | 精确版本 + 锁文件  | 精确版本 + go.sum          |
